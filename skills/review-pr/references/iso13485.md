## ISO 13485 — what to look for in a medical-device code change

- Quality-system tools: a change that alters how a quality-system tool records or decides something.
- Records: quality records that become incomplete, unreadable, editable or lost.
- Risk controls: code implementing a risk control that is changed, weakened or bypassed.
- Released versions: a change that breaks compatibility with versions already in the field or their stored data.
- Build and release: builds that stop being reproducible, unpinned versions, pipeline changes that can ship unverified software.
- Identification: the software version no longer identifiable at runtime or in records.

## IEC 62304 — what to look for by software safety class

Apply the items for the repository's class and every lower class.

- Class A and up:
  - A change that creates a new hazard or affects an existing risk control.
  - A new or bumped third-party library (SOUP) that is not identified by name, manufacturer and exact version.
- Class B adds:
  - A new third-party library with no stated functional or performance requirement.
  - Changed units or interfaces whose behaviour is left unverified.
  - Software risk controls that are not implemented or not verified by tests.
- Class C adds:
  - Lost segregation between software items that the risk analysis relies on.
  - Changed units not handling event order, data and control flow, resource allocation, faults, initialization, self-diagnostics, memory or boundary conditions.

## US and EU medical-device requirements

- Health software security: a changed attack surface with no matching security requirement.
- Usability: a change to a safety-related user interface that can cause use errors.
- Electronic records: audit trails that are not computer-generated and time-stamped, or that overwrite or hide earlier values.
- Electronic signatures: a signature that no longer shows signer, date and meaning, or can be separated from its record.
- Access to electronic records: missing authority checks or weak identification controls.
- Cyber devices: dependency changes not reflected in the software bill of materials, or vulnerabilities that can no longer be patched.
- EU software safety and security: protection against unauthorized access is weakened.
