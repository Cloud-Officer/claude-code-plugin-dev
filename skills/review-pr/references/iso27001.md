## ISO/IEC 27001:2022 Annex A — controls a code change can affect

Tag format: `[ISO27001 A.<id>]`.

- A.5.14 Information transfer — new exports, webhooks, emails, file shares or APIs that send data out: encrypted, authorised, minimal.
- A.5.15, A.5.18, A.8.2, A.8.3 Access control — every new or changed endpoint, query, job and UI action enforces authorization; ownership and tenant isolation (no IDOR); privileged/admin paths restricted.
- A.5.17, A.8.5 Authentication — password and token storage (salted adaptive hash), secure token generation, session expiry and invalidation, MFA, lockout and rate limiting on login and reset.
- A.8.4 Access to source code — changes to CODEOWNERS, branch protection, CI permissions or deploy keys.
- A.5.19–A.5.23 Suppliers and cloud services — a new third-party API, SDK or SaaS receiving data, or a changed data flow to an existing one.
- A.5.33 Protection of records — audit and business records stay immutable and retained; no new path that edits or deletes them.
- A.5.34 Privacy and PII — new personal-data fields, collection beyond need, PII sent to new places, retention.
- A.5.37, A.8.19 Operating procedures and installation — deploy, migration or ops changes without a matching runbook update.
- A.8.6 Capacity — unbounded queries, missing pagination or limits, N+1, unbounded queues or uploads.
- A.8.7 Malware — file uploads: type, size and content checks, scanning, safe storage outside the web root.
- A.8.8 Technical vulnerabilities — new or bumped dependencies: pinned, lockfile updated, no known CVE, maintained.
- A.8.9 Configuration — secure defaults, debug or verbose modes, permissive CORS, disabled security headers, IaC drift.
- A.8.10 Information deletion — deletion and retention paths actually delete (including backups, caches, search indexes).
- A.8.11, A.8.12 Data masking and leakage — secrets or PII in API responses, exports, error messages, analytics or URLs.
- A.8.13 Backup — destructive migrations without a rollback or backup step; backup settings changed in IaC.
- A.8.15, A.8.16, A.8.17 Logging and monitoring — security events logged (auth, access denied, admin actions) without secrets or PII; alerts for them; UTC timestamps.
- A.8.20–A.8.22 Network — security groups, firewall rules, public exposure, segmentation changes in IaC.
- A.8.24 Cryptography — approved algorithms, TLS certificate verification on, no hardcoded keys or secrets, key rotation possible.
- A.8.25–A.8.28 Secure development and coding — input validation, output encoding, parameterised queries, safe deserialisation, CSRF, SSRF, path traversal, least privilege.
- A.8.29 Security testing — security-relevant changes come with tests (authz denied, invalid input).
- A.8.30 Outsourced development — external contributors' changes get the same review.
- A.8.31 Environment separation — no production credentials, hosts or data in dev, test or CI config.
- A.8.32 Change management — change is traceable to a ticket, reviewed, tested and reversible.
- A.8.33 Test information — no real personal or customer data in fixtures, seeds or snapshots.
